# Measured bootstrap boundary

This report answers one narrow question: how much semantic machinery still
has to exist outside the links-defined interpreter for the current acceptance
task? It is generated by mirrored JavaScript and Rust implementations and is
checked in both test suites.

The probe loads textual LiNo, resolves and rebinds an imported rewrite
program, derives a judgement by finite inference, and executes
`links-meta-foundation` through result verification. Instrumentation is placed
at the actual host operation entry points. The same probe is then repeated
eight times with one operation disabled each time.

The `8/8` result is intentionally conservative. Calling import resolution and
inference saturation “derived” does not remove their host implementations.
They remain in the numerator and denominator until a replacement executes the
same probe without them. Likewise, a failed removal experiment establishes
dependence of this implementation, not mathematical independence, so all
eight classifications remain `UNKNOWN` rather than `INDEPENDENT`.

The versioned schema publishes the complete classification vocabulary:
`INDEPENDENT`, `DERIVABLE`, `EQUIVALENT_REENCODING`, and `UNKNOWN`.
`EQUIVALENT_REENCODING` is reserved for a removal that only recreates the same
semantic capability under another representation; such a result must not be
counted as compression. No current experiment has enough evidence for any of
the first three classifications.

## Duplication and closure

The K1 execution trace exercises linked matching, substitution, rule
selection, and result verification. The host trace beneath it still exercises
structural comparison/binding, substitution, and rewrite selection. The three
overlapping capabilities are therefore reported as observed duplication.

For the complete textual-load-through-K1-verification task, seven host
capabilities and four linked capabilities are observed. Self-hosting closure is
therefore `4 / (7 + 4) = 4/11`. This weighting is operation-based and scoped to
the named `textual-load-through-links-meta-foundation-verification` task. The
machine-readable report names all eleven capabilities; it is not a claim that
every capability has equal mathematical complexity.

## Runtime trust coverage

The current run observes four public semantic paths and 19 distinct
path/operation segments. All 4/4 paths and 19/19 segments are reachable in the
declared trust graph. Undocumented paths, operations, and path segments must
all remain zero. This check is based on execution events, not only comparison
of two manually maintained operation lists.

Run the machine-readable report with:

```bash
cd js
npm run report:bootstrap-metrics
```

The output schema is `rml-bootstrap-metrics/v1`. The bootstrap workflow prints
the full JSON report, while the JavaScript and Rust tests independently assert
the counts, removal outcomes, closure, compression, and runtime coverage.
