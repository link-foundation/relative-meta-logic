# Two meta-foundations under one linked upper layer

This note records what the Horn link-substitution foundation, the mechanism
replacement matrix, the meta-foundation comparison, the linked RML
elaboration, the local verifier provenance matrix and the assumption removal
matrix establish, and what they leave open. Every number below comes from a
committed report regenerated by an experiment script and checked by mirrored
JavaScript and Rust tests. The Rust mirrors were written without local
compilation (R169) and run only in CI.

## Horn link-substitution foundation

`lib/meta-theory/fixed-point-source.lino` is the lambda-link meta-semantics:
1446 addressed source nodes and 25 roots that define matching, substitution,
rule selection, import rebinding, inference saturation and proof lookup. Until
now it ran in two ways. The direct lambda control interprets it, and the closed
S/K path compiles it with the host bracket-abstraction compiler in
`scripts/combinator-source.mjs`.

`lib/meta-theory/horn-link-substitution.lino` runs the same unchanged source
on a third foundation, first-order Horn resolution. Its Horn clauses define:

- binder resolution, from named lambda links to positional environment links;
- substitution as environment extension and closure entry, in a Krivine-style
  call-by-name machine;
- Scott value construction from the linked roots, and observation of a value
  by applying it to marker links;
- the `rml-reduce` and `rml-prove` workflows with explicit unary fuel.

`js/src/rml-horn-link-substitution.mjs` and
`rust/relational-kernel/src/horn_link_substitution.rs` only transcribe the
validated lambda source, intern binder names injectively, cache the linked
binder-resolution answer as root facts, and convert first-order inputs and
outputs. The generic resolvers (`rml-horn-resolution.mjs`,
`horn_resolution.rs`) contain none of these predicates. The shared workload
gives the observations recorded in
`test-corpus/kernel-replacement/mechanism-observations.json`: six reductions,
two derivations, the three-step proof and the absent proof.

## Mechanism replacement on every execution

`test-corpus/kernel-replacement/mechanism-replacements.json` declares five
D to D' edits of the linked source. `experiments/definition-replacement/mechanism-matrix.mjs`
runs each on the lambda control, the compiled S/K artifact and the Horn
foundation. All three agree on every row:

| Mechanism | D' | Changed observations |
| --- | --- | --- |
| matching | keep earlier bindings without comparing | `unequal repeated binding` |
| substitution | append each head after the substituted tail | five reductions, derivations, proof, known count |
| rule selection | prefer a later applicable rule | `ordered rule choice`, `nested left traversal` |
| import rebinding | swap the two binder roles | `import rebinding`, derivations, proof |
| verification | return the first known proof | proof, absent proof |

Below the upper source, `link-substitution-replacements.json` edits the Horn
clauses themselves, on the unchanged resolver. Resolving a variable to the
outermost binder of the same name turns the shadowed-binder probe from `inner`
into `outer`. Evaluating each argument before binding it turns the unused
divergent argument probe from `kept` into a step-bound failure. The
lexical-capture probe is unchanged in both. Substitution is therefore
replaced at the linked meta-semantics level and at the foundation level. The
resolver's own unification remains a host law; the law removal below measures
which of its parts the workload needs.

## Comparison contract

`experiments/foundation-comparison/compare.mjs` writes
`test-corpus/foundation-comparison/report.json`. The upper layer is
byte-identical for both foundations: the same source SHA-256, rewritten for
neither.

| Criterion | Closed S/K | Horn resolution |
| --- | --- | --- |
| Primitive | leftmost S/K contraction on addressed doublets | unification and SLD resolution over finite link trees |
| Link-as-substitution | host bracket-abstraction compiler | linked Horn clauses |
| Preservation | same reductions, judgements and proofs | same |
| Single-law removal | each of S, K fails | 4 of 11 laws removable for this workload |
| Reduced basis | {S, K}, removal-minimal | 7 laws, removal-minimal |
| Self-interpretation | `sk-laws.lino` S/K rules; a replaced K law changes the result | the same, and a quoted Horn interpreter runs the linked substitution clauses |
| Self-description | source as addressed links | clause image described by a linked relation |
| Self-generation | not established; the host compiler generates the artifact | clause image regenerated by a linked relation |

Removal is measured against the shared workload with baseline-relative step
bounds of 1.1 times each query. Occurs check, branch-local undo, backtracking
and source clause order are removable singly and jointly; follow-bindings,
atom identity, constructor decomposition, variable orientation, standardize
apart, leftmost goal selection and answer projection are each necessary.

The two foundations are separated by an executable criterion. A lock-step
bisimulation must preserve the number of reachable distinct terminal
observations and the presence of failure. Exhaustive exploration of S/K terms
over {S, K, x} up to six leaves (34491 terms, 2298 branching states) never
reaches two normal forms, consistent with the cited Church-Rosser theorem.
One Horn goal has two distinct answers and a finitely failing sibling. A
renamed S/K control is not separated, so the criterion does not mistake
re-encoding for difference. Weaker simulations are not excluded.

The R149 gate stays open: the S/K path still compiles with a host compiler;
both foundations keep host LiNo parsing and data codecs; S/K self-generation
is not established; and minimality is relative to this workload and these law
decompositions. No ranking and no global minimality are claimed.

## Linked RML elaboration

`lib/meta-theory/horn-rml-elaboration.lino` moves the RML-specific decisions of
linked-program elaboration into Horn clauses. The host parses only generic
LiNo and encodes every atom as UTF-8 bits; `reduceSource`/`proveSource`
(JavaScript) and `reduce_source`/`prove_source` (Rust) hand those forms to the
`rml-reduce-source` and `rml-prove-source` workflows. The linked clauses decide:

- keyword spellings of program, import, rebind, rewrite, fact and inference forms;
- the pattern-variable sigil and the variable/atom split;
- form shapes, including either order of `from` and `to`;
- declaration order and per-program collection in source order;
- rejection of unknown owners and dependencies, duplicate programs and items,
  unbound replacement or conclusion variables, variable facts, missing
  premises, repeated dependencies or rebind sources, rebound variables, and
  import cycles;
- hand-off of the elaborated programs to the linked reduce and prove workflows.

The exact residual host laws on this path are, in order of use: generic LiNo
tokenization and parsing with leading-whitespace normalization; UTF-8 bit and
cons-list encoding with no sigil or keyword test; encoding of the requested
name, terms and fuel; lambda-source validation, binder interning and caching of
the linked binder resolution; the Horn resolver laws; answer decoding; and
step/depth bounds with the runtime and processor. Trust reports list the same
seven entries.

Consistency is executable. On 15 corpus documents and 2 inline documents the
linked elaboration produces exactly the programs that `LinkedProgramRegistry`
builds. On 12 invalid documents it rejects with the same decision as the host
registry, and 4 malformed documents have no linked elaboration at all. Through
the source workflows the shared observations are reproduced exactly.

Two D' edits change only the elaboration source:

| Decision | D' | Same document respelled | Unedited workload |
| --- | --- | --- | --- |
| pattern-variable sigil | `$` instead of `?` | baseline observations | five reductions, derivations, proof and known count change |
| rewrite keyword | `rewrite-rule` instead of `linked-rewrite` | baseline observations | five reductions change |

Removing the sigil fact or the program keyword leaves no elaboration. The host
registry still reads the respelled documents by its own rules, so on this path
the linked definition alone decides.

Limits: the elaboration collects items per program, quadratic in the number of
forms. `test-corpus/linked-dispatch/typed-recursion-source.lino` (46 KB) did
not finish within 50 million resolution steps. The resolver's input depth
bound of 512 limits a document to a few hundred forms. Every other path (the
S/K and lambda backends, the checker, the compiler and code generation) still
uses host elaboration. This advances R151/R132/R55 for linked-program
elaboration only.

## Local verifier provenance

`lib/meta-theory/horn-local-verifier.lino` executes the `linkedVerifierStep`
local join of `rml-foundation-search.mjs` as Horn clauses and reproduces its
seven probe cases and traces exactly. `experiments/verifier-provenance/removal-matrix.mjs`
then removes one operation at a time over 14 cases and writes
`test-corpus/verifier-provenance/report.json`:

- 19 of 25 linked clauses change some case when removed. The other 6 change
  none for these inputs: three code-equality branches, two `all-yes`
  branches, and the end of the presence scan.
- Both declared readings change the trace on identical Links. Reading
  correspondences from the second slot turns the complete match into `ZERO`
  and the slot-reversed copy into `ONE`. Reading presence as proof
  multiplicity turns a duplicated description from `ONE` into `MANY`.
- 8 of 10 resolver laws are needed. Occurs check and leftmost goal
  selection change no case. Source clause order changes only the trace
  sequence of the three multi-answer cases.
- The host operations still needed are exhaustive answer enumeration (without
  it every `MANY` becomes `ONE`) and an injective address codec (without it
  every case becomes `MANY`). Classification and trace-address allocation
  remain host steps.
- Renaming preserves the trace up to renaming. Record order preserves the
  match set but not the trace sequence. A relocated description matches only
  with its moved mapping. A trace replays by the same join.

The trace therefore does not follow from the input Links alone. It follows
only together with the declared readings and the resolver laws. This
advances R143/R144 with a complete one-at-a-time removal matrix for this local
verifier and with duplicated and relocated descriptions. It does not authorize
a reading or close the authority boundary.

## Assumption removal matrix

`experiments/assumption-removal/matrix.mjs` starts from the four assumptions
that the `sharedAddressComposition` audit retains. It removes one at a time
by exhaustive enumeration and writes `test-corpus/assumption-removal/report.json`.
Base counts for one slot (2, 10, 77, 799 classes for 1 to 4 links) equal the
audit's.

| Removed assumption | Effect | Classes after removal |
| --- | --- | --- |
| ordered link records | identifies | 2, 7, 20, 61 (one slot); 5, 85, 1855 (two slots) |
| ordered reference slots | identifies | 4, 66, 2406 (two slots, 1 to 3 links) |
| fixed slot orientation (uniform reversal) | identifies | 4, 85, 5328 |
| distinct link addresses | separates | 2, 15, 203, 4140; 5, 203, 21147 |
| one fixed arity (1 or 2 slots) | separates | 7, 235, 17419 |
| equality as the only observation (observer order added) | separates | 3, 62, 3210, 310344; 13, 4142, 5544342 |

Each identifying row has a first witness pair. The non-faithfulness of local
single-link descriptors survives every identifying removal from two links
onward, and per-record slot exchange identifies at least as much as uniform
reversal. No assumption is thereby shown intrinsic or eliminable for links in
general, and R71/R73/R74 stay open.

### Removing finiteness

Finite enumeration cannot remove finiteness, so
`experiments/assumption-removal/finiteness.mjs` removes it separately and
writes `test-corpus/assumption-removal/finiteness.json`. Finiteness is replaced
by finite presentation: an affine one-slot structure has the record
`[n, n + step]` for every integer `n` from its start, or for every integer.

- **Forcing fact.** Every self-embedding of a finite structure is onto. An
  embedding is an injective address map that sends records to records, so
  deleting a link is always observable. This was checked exhaustively over
  the audited one-slot classes (2, 10, 77 and 799 structures; 2, 14, 120 and
  1464 self-embeddings). None of the embeddings is non-surjective, and no
  single-link deletion is invisible.
- **Removal.** The shift `x -> x + 1` is a symbolic, non-surjective
  self-embedding of the forward ray `[n, n+1]` (n ≥ 0). It is also one for the
  backward ray `[n, n-1]` (n ≥ 1). Each ray is therefore identified with the
  proper substructure left after deleting its first link. A concrete prefix
  check confirms the certificate on every window of up to 32 records.
- **Which deletions stay visible.** Two isomorphism invariants decide each
  deletion: atoms (referenced addresses that are not links) and unreferenced
  links. Deleting the first link of a ray is the only invisible deletion. Any
  later deletion leaves a dangling reference, which changes `(0, 1)` to
  `(1, 2)` for the forward ray and `(1, 0)` to `(2, 1)` for the backward ray.
  The two-sided line `[n, n+1]` over all integers has no invisible deletion,
  because its shift is onto. Both slot orientations behave alike.

The deletion invariants cover the first 24 deletions. Windows of radius 4
and 8 agree on every one of them, which checks that the structure is uniform
beyond the start. This does not show finiteness intrinsic or eliminable for
links in general.

## Conditional continuation join at every small width

`conditionalContinuationProbe` reports its observations for one chain,
`[3,0,1]`, `[4,1,2]` with witness `[5,3,4]`.
`experiments/continuation-join/exhaustive.mjs` applies the same join to every
ordered addressed binary structure with three records (1855 classes) and four
records (56400 classes), up to renaming and record order, and writes
`test-corpus/continuation-join/report.json`:

| Observation on the probe chain | Three records | Four records |
| --- | --- | --- |
| uniform slot reversal reverses the continuation | holds everywhere | holds everywhere |
| adding the result record keeps the join | holds everywhere | holds everywhere |
| witness orientation is dispensable | fails in 72 classes | fails in 4244 classes |
| the two projections give different pairs | agree on 15 non-empty joins | agree on 689 |
| each supporting record is needed | holds | 103 of 4786 output pairs survive one removal |
| the result is not yet recorded | already recorded in 32 classes | in 1584 |

Reversal equivariance and monotonicity are general for these widths, and
monotonicity holds at every width because the join is a positive existential
query. The other single-chain observations belong to that chain, not to the
join. This advances R145/R146 by separating them, and it neither makes the
join intrinsic nor authorizes a projection.

```sh
node experiments/definition-replacement/mechanism-matrix.mjs
node experiments/foundation-comparison/compare.mjs
node experiments/verifier-provenance/removal-matrix.mjs
node experiments/assumption-removal/matrix.mjs

node experiments/continuation-join/exhaustive.mjs
node --test js/tests/horn-link-substitution.test.mjs js/tests/mechanism-replacement.test.mjs \
  js/tests/meta-foundation-comparison.test.mjs js/tests/horn-rml-elaboration.test.mjs \
  js/tests/verifier-provenance.test.mjs js/tests/assumption-removal.test.mjs \
  js/tests/continuation-join.test.mjs
cargo test --manifest-path rust/relational-kernel/Cargo.toml
cargo test --manifest-path rust/Cargo.toml --test assumption_removal_tests --test continuation_join_tests
```

The Rust mirrors that need the Horn resolver are `horn_link_substitution_tests.rs`,
`meta_foundation_comparison_tests.rs`, `horn_rml_elaboration_tests.rs` and
`verifier_provenance_tests.rs` under `rust/relational-kernel/tests/`. The
enumeration mirrors `assumption_removal_tests.rs` and
`continuation_join_tests.rs` need only the main crate and live in `rust/tests/`. The JavaScript elaboration test compares
every shared observation under each D'. To stay within the companion CI time
limit, its Rust mirror compares the elaborated programs and one reduction per
document instead.
