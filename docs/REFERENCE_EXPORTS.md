# Exact reference names in proof exports

Lean and Rocq export every source identifier as `rml_ref_` followed by the lowercase hexadecimal encoding of its exact UTF-8 bytes. Empty labels end at the prefix. Names containing controls, spaces, punctuation, Unicode, keywords, or the prefix itself remain distinct. Declaration, reference and binder occurrences use the same mapping. This deliberately changes generated spelling, including ordinary ASCII names. `Type` and `Prop` retain their builtin meanings in type positions; unsupported rebinding is rejected explicitly.

Isabelle global names use the existing recorded unique-name mapping. Bound variables use `v_ref_` plus UTF-8 hex, so distinct source names cannot capture each other or an `rml_` global name. Source display functions remain human-readable; exact transport uses `emitLinoTerm` / `emit_lino_term`.

`scripts/reference-export-fixtures.mjs` constructs compiler smoke artifacts from the shared reference corpus and records source-to-target mappings. Each language gets accepted programs that prove nested functions return the first argument and retain an unrelated global constant, plus separate deliberately false capture and rebinding claims. The fixture includes an atom beginning with the generated prefix, empty/control/Unicode labels, trailing punctuation and language keywords. Builtin rebinding controls are tested at the exporter boundary.

JavaScript/Rust string and AST tests establish mapping and source-generation properties. Emitting these files is not native validation. Lean, Rocq and Isabelle must each accept their positive artifact and reject both negative proofs under the exact supported compiler version before exporter compiler validity is claimed. Existing whole-language translation obligations are unchanged.

Emit reviewable artifacts with `node scripts/check-reference-exports.mjs`. To validate an installed compiler, run the driver through `scripts/run-with-cache.mjs` with `--language=Lean`, `--language=Rocq`, or `--language=Isabelle`; `--compiler=PATH` selects its exact executable. Supported versions are Lean 4.34.1, stable Rocq 9.3.0, and Isabelle2025-2. Each compiler subprocess has a 120-second limit. All generated artifacts remain under the registered `.rml-cache/compiler` class; archive its receipt and logs before normal full cleanup. Isabelle uses its supported `USER_HOME` setting, verifies every user/heap/browser/temporary directory is inside that cache, and builds one thread at a time. This driver is an external validation oracle, not the implementation of RML semantics.

Caller-supplied ASTs use the same 64-level nesting and 10 MiB emitted-source limits as LiNo document ingress. JavaScript rejects cyclic arrays explicitly and accepts shared acyclic subtrees without mutation. Rust's owned `Node` tree cannot express cycles; `try_emit_lino_term` returns a diagnostic string for over-limit trees. The String-returning emitter reports that boundary with an explicit panic rather than recursing until stack exhaustion.

The `formal-corpus` workflow runs these controls after the existing Lean/Rocq corpus builds, and in a separate Isabelle job. The official [Isabelle installation page](https://isabelle.in.tum.de/installation.html) names publisher `makarius/isabelle` and release `Isabelle2025-2`; CI pins the freshly verified registry digest recorded in `docs/case-studies/issue-183/data/isabelle-reference-oracle-image.json`. Compact reports are archived by the cache wrapper before cleanup, and job artifacts upload under `if: always()` before full teardown. A configured CI job is not a passing compiler result.

Lean and Rocq compiler controls run separately for JavaScript and Rust. `--runtime=rust` invokes the public `rml export lean|rocq` CLI built in this checkout and records its binary hash, implementation pins and emitted-source hash. Both producers use the same RML input and the same positive, false-capture and false-rebinding proof statements. Rust artifacts and their report live in separate `Rust` subdirectories; their receipt is `receipt-rust.json`.

For a container compiler, `--prepare-only` creates the Rust artifacts on the host and `--validate-prepared` verifies the current implementation pins, producer binary, input and each exact compiler-source hash before compiling. This keeps the host executable out of the container execution path. CI builds the CLI and consumes its artifacts within one normal cache lifecycle operation. The default `--runtime=js` preserves the JavaScript path. Isabelle is explicitly JavaScript-only because RML has no Rust Isabelle exporter. Unit mocks validate this orchestration contract; only runs using the real Rust CLI and the pinned native compilers establish exporter/compiler validity.

Lean definitions that reference declared axioms or earlier noncomputable definitions carry an explicit `noncomputable` modifier. Dependency tracking respects exact lambda binders and local shadowing, and does not treat binder type annotations as value dependencies. Parameter-only definitions remain ordinary `def` declarations. This annotation belongs to the exporter output, so the compiler smoke fixtures validate the actual generated artifact without an added section that would conceal a missing modifier. Rust Lean/Rocq exporters share the core binder parser, including prefix binders whose names end in punctuation.
